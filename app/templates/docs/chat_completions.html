Запрос

HTTP
POST {{ features.api_base_url }}/v1/chat/completions

Обязательные заголовки — Authorization и Content-Type: application/json.

Параметры тела

ПолеТипОписание
modelstringОбязательное. Алиас модели из раздела Модели и цены.
messagesarrayОбязательное. Массив сообщений в формате OpenAI.
streamboolОтдавать ответ по частям. См. Потоковые ответы.
max_tokensintПредел длины ответа. Всегда ограничивается сверху потолком сервиса ({{ max_output_tokens_cap }}).
temperature, top_pnumberУправление разнообразием ответа.
stopstring / arrayСтроки, на которых генерация прекращается.
response_formatobjectНапример {"type": "json_object"}.
tools, tool_choicearray / objectВызов функций в формате OpenAI.
presence_penalty, frequency_penaltynumberШтрафы за повторы.
seed, n, logprobs, top_logprobs—Передаются провайдеру как есть.

Поля, которых нет в списке, отбрасываются и до провайдера не доходят. Параметры, которые конкретная модель не поддерживает, тоже молча отбрасываются — один и тот же запрос можно слать разным моделям.

Предел длины ответа

Сервис всегда подставляет ограничение на длину ответа, даже если вы его не прислали, и зажимает ваше значение сверху потолком {{ max_output_tokens_cap }}. Причина денежная: под каждый вызов резервируется сумма на балансе, и без верхней границы длины ответа резерв невозможно оценить.

Повтор без двойного списания

Сеть может оборвать соединение после того, как запрос ушёл в работу. Чтобы повтор не списал деньги второй раз, передайте заголовок Idempotency-Key с произвольной уникальной строкой. Повтор с тем же ключом вернёт сохранённый ответ первого запроса и не пойдёт к провайдеру.

HTTP
Idempotency-Key: order-8813-retry-1

Тот же ключ с другим телом запроса вернёт 409 (idempotency_key_reused) — так сервис не отдаст вам чужой закэшированный ответ.

Потоковые ответы по ключу не повторяются: сохранять поток для повтора нечем.
