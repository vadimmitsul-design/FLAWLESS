Формат заголовка

Каждый запрос к API несёт заголовок Authorization со схемой Bearer. Другие способы передачи ключа — параметр строки запроса, cookie — не поддерживаются намеренно: ключ не должен попадать в логи веб-сервера и в историю браузера.

HTTP
Authorization: Bearer nh_xxxxxxxxxxxxxxxxxxxxxxxx
Content-Type: application/json

Как устроен ключ

  • ключ начинается с префикса nh_ — по нему его легко узнать в утечке или в логе;
  • в базе хранится только SHA-256 от ключа, само значение сервис не знает;
  • ключ показывается один раз при выпуске — дальше в кабинете видны только последние 4 символа;
  • ключей может быть несколько: удобно развести прод, тесты и подрядчика.

Ограничения на уровне ключа

У каждого ключа есть собственные дневной и месячный потолки расхода. Они действуют внутри общего потолка аккаунта и не могут его превысить — так можно выдать ключ на ограниченную сумму, не рискуя всем балансом.

Выпуск второго ключа не обходит потолок аккаунта: лимит кошелька проверяется отдельно от лимита ключа, и превышение любого из них останавливает запрос.

Отзыв

Ключ отзывается в кабинете и перестаёт действовать немедленно — перезапуск сервиса не нужен. Отключение аккаунта целиком тоже мгновенно делает недействительными все его ключи.
