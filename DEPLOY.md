# Развёртывание внутреннего контура на сервере по IP

Внутренний экземпляр — кабинет для сотрудников компании: доступ к моделям,
бюджеты и потолки расхода, учёт прокси и подписок со сроками. Домена у него
нет и не планируется.

**Код общий с клиентским экземпляром, раздельны только настройки, база и
порты.** Это осознанное решение: различается между контурами дешёвое
(витрина, регистрация, магазин, наценка) и оно вынесено в флаги, а общий —
биллинг, ради которого форк означал бы две копии денежного кода и починку
каждой ошибки дважды.

---

## Что понадобится заранее

1. **Ключ OpenRouter с деньгами на балансе.** Без него не работает ничего:
   все модели в `config/models.yaml` ходят через OpenRouter, и каждый вызов
   упадёт на авторизации. Проверить — `scripts/preflight.py` (ниже).
2. **Сервер с Docker и docker compose.** Минимум — 2 ГБ памяти: рядом живут
   приложение и Postgres.
3. **Решение по доступу** — см. «Как закрыть доступ» ниже. Принять его нужно
   ДО того, как сервис окажется в сети.

---

## Порядок

### 1. Перенести код и настройки

```bash
git clone <репозиторий> /opt/flawless
cd /opt/flawless
```

Файл `.env.internal` в репозитории **нет и быть не должно** — он в
`.gitignore` вместе со всеми `.env.*`, потому что содержит ключи. Соберите
его на сервере из `.env.internal.example` и заполните:

```bash
cp .env.internal.example .env.internal
# и отредактируйте
```

Обязательно заполнить:

| Переменная | Чем |
|---|---|
| `SESSION_SECRET` | 64 случайных символа: `openssl rand -base64 48` |
| `POSTGRES_PASSWORD` | ещё одна случайная строка, не «neurohub» |
| `OPENROUTER_API_KEY` | ключ с балансом |
| `ENV_FILE` | ровно `.env.internal` — см. грабли ниже |

`TELEGRAM_BOT_TOKEN` оставить **пустым**: боевой токен занят клиентским
экземпляром, а два процесса с одним токеном воруют друг у друга сообщения.

### 2. Проверить настройки до запуска

```bash
python scripts/preflight.py .env.internal
```

Скрипт ловит ровно те ошибки, на которых этот проект уже терял время:
файл настроек, не назвавший сам себя; слабый или забытый `SESSION_SECRET`;
пароль Postgres из умолчания; отсутствующий ключ провайдера; совпадающие
порты или один токен Telegram у двух экземпляров. Ненулевой код возврата —
разворачивать нельзя.

### 3. Поднять

```bash
docker compose -p flawless-internal --env-file .env.internal up -d --build
```

**Флаг `--env-file` нужен КАЖДОЙ команде compose для этого экземпляра, не
только первой.** Без него берутся настройки основного `.env`, и контейнер
лезет на чужие порты. Ошибка выглядит как «Bind for 127.0.0.1:5434 failed» и
на настоящую причину не намекает.

### 4. Завести администратора и прайс

```bash
docker compose -p flawless-internal --env-file .env.internal exec neurohub \
  python scripts/seed_prices.py

docker compose -p flawless-internal --env-file .env.internal exec neurohub \
  python scripts/manage_admin.py --email you@company.ru --name "Имя" --password '<пароль>'
```

Пароль передавайте в одинарных кавычках. Пустой и короче восьми символов
скрипт теперь отвергает — однажды так завели администратора вообще без
пароля, потому что переменная оболочки оказалась пустой.

### 5. Проверить

```bash
curl -s http://127.0.0.1:8040/healthz
```

Ответ должен содержать `"status":"ok"` и `"models_ready"` больше нуля.
`models_ready: 0` означает, что база жива, а вызвать нечего — прайс не
засеян или ключа нет.

## Как закрыть доступ

Приложение слушает порт 8040. По умолчанию `APP_BIND=0.0.0.0` — это значит,
что **порт открыт всему интернету**, и пароли сотрудников идут по HTTP
открытым текстом. Выберите одно:

**Вариант А — фаервол (просто).** Оставить `APP_BIND=0.0.0.0` и пустить на
порт только офисные адреса:

```bash
ufw allow from <офисный-IP> to any port 8040 proto tcp
ufw deny 8040
```

Пароли всё равно идут в открытом виде внутри разрешённой сети.

**Вариант Б — SSH-туннель (безопасно, но по одному).** Поставить в
`.env.internal` строку `APP_BIND=127.0.0.1`: снаружи порт не виден вовсе,
каждый сотрудник ходит через `ssh -L 8040:127.0.0.1:8040 user@сервер`.

**Вариант В — TLS с самоподписанным сертификатом.** Nginx перед
приложением. Браузер будет ругаться на сертификат при каждом заходе.

Порт базы (5436) уже привязан к `127.0.0.1` в `docker-compose.yml` и наружу
не смотрит ни при каком варианте. Не меняйте это.

**`ENVIRONMENT` держите в `development`, пока перед приложением нет HTTPS.**
В режиме `production` сессионная кука получает флаг `Secure` и по обычному
HTTP браузером не отправляется: вход молча перестанет работать, и в логах об
этом не будет ни строчки.

## Обновление

```bash
cd /opt/flawless && git pull
docker compose -p flawless-internal --env-file .env.internal up -d --build
```

Миграции накатываются сами при старте контейнера (`alembic upgrade head` в
команде запуска). Отдельного шага не нужно.

## Резервные копии

`scripts/backup_db.sh` сейчас знает только про основной экземпляр — у
внутреннего копий нет. Пока в нём нет данных, которые жалко потерять, это
осознанно отложено. **Вернуться к этому нужно в тот день, когда сотрудники
начнут им реально пользоваться:** балансы, история вызовов и журнал платежей
за подписки существуют только в томе `flawless-internal_pgdata` и
восстановить их неоткуда.

И помните: `docker compose down` **не удаляет** именованный том. Старый том с
прежним паролем заставит Postgres пропустить инициализацию и оставить
прежние учётные данные — приложение уйдёт в бесконечный рестарт с
`password authentication failed`, при том что все три копии пароля совпадают
побайтно. Диагноз виден только в первых строках лога базы.

## Что в этом контуре выключено намеренно

Витрина и маркетинговые страницы, магазин подписок, платные промпты, детские
аккаунты, архив диалогов, Telegram-бот. Регистрация — только по приглашению
от администратора. Выключенный раздел отдаёт 404, а не прячет ссылку.
